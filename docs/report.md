## Введение

Современные компьютерные сети подвержены широкому спектру угроз, включая DDoS-атаки, сканирование портов, распространение вредоносного ПО и утечки данных. Традиционные сигнатурные методы обнаружения вторжений эффективны против известных атак, но неспособны выявлять новые, ранее не встречавшиеся угрозы. В связи с этим актуальной задачей является разработка платформы, способной обнаруживать аномалии сетевой активности на основе анализа потоковых данных с использованием методов машинного обучения.

Данный проект посвящен разработке такой платформы, включающей модули сбора сетевого трафика, потоковой обработки данных, извлечения признаков, а также детектирования аномалий с использованием алгоритмов машинного обучения и правил.

Основные задачи платформы: захват сетевого трафика в режиме реального времени или из PCAP-файлов, агрегация данных во временные окна с вычислением статистических признаков, обнаружение аномалий методами Isolation Forest, LOF и One-Class SVM, визуализация результатов и сохранение обученных моделей.

## 1. Формирование требований к системе

### 1.1 Анализ существующих подходов

Системы обнаружения вторжений (IDS) делятся на три категории:

- **Сигнатурные** — сравнивают трафик с базой известных сигнатур атак (Snort, Suricata, Zeek)
- **Аномалийные** — выявляют отклонения от нормального профиля сетевой активности (статистические методы, ML)
- **Гибридные** — комбинируют оба подхода

**Методы машинного обучения для обнаружения аномалий:**

- **Isolation Forest** — эффективный метод обнаружения аномалий в многомерных данных, основанный на изолировании выбросов с помощью случайных деревьев решений
- **LOF (Local Outlier Factor)** — метод, основанный на локальной плотности объектов; точки с аномально низкой плотностью относительно соседей считаются выбросами
- **One-Class SVM** — метод опорных векторов для одного класса, строит границу вокруг нормальных данных

**Сравнительный анализ подходов:**

| Метод | Преимущества | Недостатки |
|-------|-------------|------------|
| Сигнатурный | Низкий уровень ложных срабатываний | Не обнаруживает новые атаки |
| Статистический | Простота реализации, интерпретируемость | Чувствителен к выбору порогов |
| Isolation Forest | Эффективен для многомерных данных, устойчив к выбросам | Требует настройки гиперпараметров |
| One-Class SVM | Хорошо работает на размеченных данных | Медленен на больших объёмах |
| LOF | Не требует предположений о распределении данных | Чувствителен к выбору k-соседей |

### 1.2 Функциональные требования

К функциональным требованиям относятся:

- **RF-01**: Сбор сетевого трафика в режиме реального времени (live capture) и из PCAP-файлов
- **RF-02**: Извлечение признаков из сетевых пакетов (IP-адреса, порты, протоколы, размеры, временные метки, флаги TCP)
- **RF-03**: Потоковая агрегация данных в окнах времени с вычислением статистических характеристик (среднее, стандартное отклонение, энтропия, количество уникальных значений)
- **RF-04**: Обнаружение аномалий с использованием алгоритмов машинного обучения (Isolation Forest, LOF, One-Class SVM) и правил (rule-based detection)
- **RF-05**: Визуализация результатов обнаружения (графики временных рядов, confusion matrix, ROC-кривая, распределение аномалий)
- **RF-06**: Модульная архитектура для независимой замены/добавления алгоритмов обнаружения
- **RF-07**: Сохранение и загрузка обученных моделей
- **RF-08**: Генерация синтетических сетевых данных для тестирования (DDoS, port scan, bruteforce, data exfiltration)

### 1.3 Нефункциональные требования

К нефункциональным требованиям относятся:

- **RNF-01**: Обработка не менее 1000 пакетов/сек на стандартном оборудовании
- **RNF-02**: Модульная архитектура, позволяющая расширять функциональность без переработки существующего кода
- **RNF-03**: Кроссплатформенность (Windows, Linux, macOS)
- **RNF-04**: Воспроизводимость результатов за счёт использования детерминированных алгоритмов
- **RNF-05**: Читаемость кода, соответствие стандартам PEP 8

## 2. Архитектура приложения

### 2.1 Обоснование выбора технологий

**Scapy** — библиотека для захвата, анализа и генерации сетевых пакетов. Выбрана благодаря гибкости, поддержке множества протоколов и возможности как live-захвата, так и работы с PCAP-файлами.

**Pandas + NumPy** — основа для обработки данных. Pandas обеспечивает удобные структуры данных (DataFrame) и богатый набор функций для агрегации, фильтрации и анализа. NumPy используется для численных расчётов, включая вычисление энтропии.

**Scikit-learn** — библиотека машинного обучения, предоставляющая готовые реализации Isolation Forest, Local Outlier Factor и One-Class SVM.

**Matplotlib + Seaborn** — библиотеки для визуализации данных. Позволяют строить временные ряды, гистограммы, heatmap, ROC-кривые и другие графики, необходимые для анализа результатов.

### 2.2 Схема архитектуры

Платформа реализована по модульному принципу "конвейерной обработки" (pipeline), где каждый этап обработки данных выполняется независимым модулем:

```
[Packet Capture] --> [Feature Extraction] --> [Anomaly Detection] --> [Visualization]
       |                      |                        |
  - Live capture        - Window aggregation     - Isolation Forest
  - PCAP import         - Statistical features   - LOF
  - Synthetic gen.      - Entropy metrics        - One-Class SVM
                                                   - Rule-based rules
```

## 3. Реализация модуля сбора и потоковой обработки сетевых событий

### 3.1 Модуль сбора данных

Модуль сбора (`src/collector/packet_capture.py`) реализует два основных класса:

**PacketCapture** — обеспечивает захват сетевого трафика из двух источников:

- Live-захват через интерфейс с использованием Scapy (асинхронная обработка пакетов в отдельном потоке)
- Загрузка PCAP-файлов через `rdpcap()`

Для каждого пакета извлекаются базовые признаки: IP-адреса источника и назначения, протокол (TCP/UDP/ICMP), длина пакета, TTL, порты, TCP-флаги.

**PacketGenerator** — генератор синтетических данных для тестирования. Поддерживает генерацию четырёх типов аномального трафика:

- **DDoS** — множество SYN-пакетов с разных IP на 80 порт с высокой частотой
- **Port scan** — одиночные SYN-пакеты с одного IP на множество различных портов
- **Bruteforce** — последовательные TCP-соединения на 22 порт (SSH)
- **Data exfiltration** — крупные TCP-пакеты на внешний IP

Метод `generate_mixed_traffic()` создаёт реалистичный сетевой трафик, комбинируя нормальную активность с заданными типами атак.

### 3.2 Модуль потоковой обработки

Модуль обработки (`src/processing/feature_extractor.py`) реализует класс `FeatureExtractor`, который выполняет агрегацию сырых пакетов во временные окна.

**Метод `aggregate_window()`** группирует пакеты по временным окнам фиксированного размера (по умолчанию 2 секунды) и вычисляет для каждого окна 23 признака:

- **Количественные**: packet_count, bytes_total, bytes_mean, bytes_std, bytes_min, bytes_max
- **Сетевые**: unique_src_ip, unique_dst_ip, unique_src_port, unique_dst_port
- **Протокольные**: proto_tcp, proto_udp, proto_icmp, syn_count, syn_ratio
- **Временные**: packets_per_sec, bytes_per_sec
- **Энтропийные**: src_entropy, dst_port_entropy — мера разнообразия IP-адресов и портов

Энтропия вычисляется по формуле:

$$H = -\sum_{i} p_i \cdot \log_2(p_i + \epsilon)$$

где \(p_i\) — доля каждого уникального значения в окне, \(\epsilon = 10^{-10}\) — регуляризатор для избежания логарифма нуля.

## 4. Разработка алгоритмов выявления аномалий сетевой активности

### 4.1 Ансамбль методов обнаружения

Модуль обнаружения (`src/detection/detector.py`) предоставляет два подхода:

**Machine Learning детекторы (класс `AnomalyDetector`)**:

1. **Isolation Forest** — строит ансамбль случайных деревьев решений, изолирующих аномальные точки за меньшее количество разбиений. Параметры: количество деревьев (100), contamination (0.15).

2. **Local Outlier Factor (LOF)** — вычисляет локальную плотность каждого объекта относительно k ближайших соседей. Аномалиями считаются объекты с аномально низкой плотностью. Параметры: n_neighbors (20), contamination (0.15).

3. **One-Class SVM** — строит разделяющую гиперплоскость, отделяющую нормальные данные от выбросов. Параметры: kernel (rbf), nu (0.15).

**Rule-based детектор (класс `RuleBasedDetector`)** — набор из пяти эвристических правил:

- **high_syn_ratio** — более 80% SYN-пакетов в окне (признак SYN-flood)
- **high_packet_rate** — более 5000 пакетов/сек (признак DDoS)
- **high_port_entropy** — энтропия портов > 5 (признак port scan)
- **many_unique_ports** — более 50 уникальных портов назначения (признак port scan)
- **low_packet_rate_high_bytes** — мало пакетов, но высокий объём данных (признак exfiltration)

### 4.2 Результаты сравнения методов

Для оценки качества было проведено сравнение трёх ML-методов на синтетическом наборе данных (5750 пакетов, 750 аномальных). Результаты:

| Метод | Precision | Recall | F1-Score | Accuracy |
|-------|-----------|--------|----------|----------|
| Isolation Forest | 0.1579 | 1.0000 | 0.2727 | 0.8720 |
| LOF | 0.2000 | 1.0000 | 0.3333 | 0.9040 |
| One-Class SVM | 0.1579 | 1.0000 | 0.2727 | 0.8710 |

*Таблица 1. Сравнение методов обнаружения аномалий*

Все три метода показали Recall = 1.0 (100% обнаружение аномалий), однако имеют ложноположительные срабатывания (FPR ~10-13%). Лучший результат по F1 показал LOF (0.3333). Rule-based детектор показал 1 срабатывание за весь период.

## 6. Управление проектом

### 6.1 Методология управления

В ходе выполнения проекта была применена **гибридная методология управления**, сочетающая элементы классического водопадного (Waterfall) и итеративного подходов.

**Этапы 1-2 (анализ и архитектура)** выполнялись по водопадной модели: каждый этап имел чётко определённые входные и выходные документы. Результаты этапа 1 (требования) являлись неизменной базой для этапа 2 (архитектура).

**Этапы 3-5 (реализация, алгоритмы, тестирование)** выполнялись итеративно с возможностью параллельной разработки модулей. Модульная архитектура позволила независимо разрабатывать:

- Модуль сбора трафика
- Модуль обработки и извлечения признаков
- Модуль обнаружения аномалий
- Модуль визуализации

Каждая итерация завершалась запуском тестов и проверкой работоспособности.

2. Спроектирована модульная архитектура платформы, обеспечивающая независимость компонентов сбора, обработки, детектирования и визуализации.

3. Реализован модуль сбора сетевого трафика, поддерживающий live-захват, загрузку PCAP-файлов и генерацию синтетических данных с 4 типами атак (DDoS, port scan, bruteforce, data exfiltration).

4. Разработан модуль потоковой обработки, выполняющий агрегацию пакетов во временные окна с вычислением 23 статистических признаков, включая энтропийные метрики.

5. Реализованы и сравнены три алгоритма машинного обучения (Isolation Forest, LOF, One-Class SVM) и rule-based детектор. Лучший результат показал LOF (F1 = 0.3333, Recall = 1.0, Accuracy = 0.904).

6. Создан модуль визуализации, генерирующий 8 типов графиков для анализа результатов.

7. Написаны 19 автоматизированных тестов, все успешно проходят.

Платформа может быть расширена за счёт добавления новых алгоритмов обнаружения, интеграции с системами потоковой передачи данных (Apache Kafka), поддержки большего числа протоколов и внедрения нейросетевых методов (Autoencoder, LSTM).
